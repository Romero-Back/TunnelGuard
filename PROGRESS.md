# Ход разработки TunnelGuard

Цель проекта — системный kill switch на macOS для Claude Desktop и Claude Code. При обрыве VPN приложения теряют сеть, при восстановлении снова получают доступ. Первые испытания используют один VPN-клиент и тестовый процесс.

## Что уже проверено

- Mac на Apple Silicon. Повторно прошли все семь проверок статического профиля sing-box. Они покрывают проверку JSON, а сетевую блокировку ещё предстоит испытать.
- `Sources/FilterProbe/main.swift` содержит пробный `NEFilterDataProvider`. Он должен блокировать новые соединения только для тестового бинарника с идентификатором подписи `app.tunnelguard.lab.networkprobe`. Фильтр ещё не загружался в macOS.
- Основной клиент для испытаний — **V2Pro**. При подключении `ifconfig -v` показал активный Packet Tunnel, а `netstat` — маршруты IPv4 и IPv6 через него. `scutil --nc status V2Pro` в тот же момент показывал `Disconnected`. Имя интерфейса определяется динамически.
- Официальный sing-box (SFM) остаётся запасным вариантом. Конфиг VPN и данные доступа для разработки не требуются.

## Первый практический шаг выполнен

- SwiftPM и `Packaging/macOS/build-lab.sh` собрали `TunnelGuardLab.app` с вложенным расширением `app.tunnelguard.lab.filter.systemextension` и отдельную CLI-пробу `tunnelguard-network-probe`. Приложение подготавливает конфигурацию фильтрации сокетов в памяти. Код активации и запись сетевых настроек относятся к следующему шагу.
- Проверены структура пакетов, наличие класса провайдера в исполняемом файле и локальная ad hoc подпись пробы с нужным идентификатором. Проба установила TCP-соединение и получила UDP-эхо на `127.0.0.1` и `::1`. Также проверены таймаут UDP, несовпадающий ответ и неверные аргументы. Испытания фильтра и отключения V2Pro ещё впереди.
- Локальная сборка подтверждена на Command Line Tools. Также доступны `codesign`, `notarytool` и `stapler`. Keychain показал 0 действительных идентификаторов подписи. Для прямой установки нужны сертификат `Developer ID Application` с приватным ключом, два соответствующих профиля и нотарификация. Параметры профилей и entitlements записаны в [README.md](README.md). Пакеты приложения и расширения пока без подписи Developer ID.

## Бесплатный вариант

По требованию пользователя весь проект должен работать бесплатно. Дальнейшие испытания идут через `Scripts/tunnelguard-run.py`, без подписки и системного расширения. Встроенная песочница ограничивает команду и её потомков одним локальным TCP-портом. Локальный HTTPS-прокси привязывает внешние IPv4/IPv6-сокеты к подтверждённому интерфейсу V2Pro, а DNS выполняет через Cloudflare DoH с такой же привязкой. Настройки сети Mac не менялись.

На подключённом V2Pro прошли HTTPS по доменному имени и по адресу IPv6. Прямая попытка соединения в обход прокси была заблокирована. `claude --version` работает из песочницы. Дополнительные проверки в `Tests/check_free_launcher.py` покрывают сетевые ограничения дочернего процесса, привязку к интерфейсу, отказ при пропаже маршрута и закрытие активного соединения в симуляции.

Текущий этап — проверка сетевого ядра. Для запуска команды требуется `--expected-egress` с ожидаемыми публичными IP VPN. Перед разрешением соединения для соответствующего семейства IP прокси сверяет Cloudflare и ipify с этим списком. Без списка доступен только фиксированный диагностический запрос. IPv4 на текущем профиле подтверждён двумя источниками. Проверка через IPv6-сокеты тоже показала IPv4 на выходе, поэтому строгий режим блокирует IPv6-назначения. Проверено сохранение песочницы после принудительного завершения прокси. Установленный Claude Code отправил тестовый HTTPS-запрос через CONNECT и обработал ответ локального имитатора API без доступа к настоящей учётной записи.

## Интерфейс TunnelGuard

`TunnelGuard.app` 0.3.0 запускает обычный `/Applications/Claude.app` и проверяет его доступ через V2Pro. PID Claude и его Electron Helper проверены в выделенной группе. Графическое окно виртуалки относилось к версии 0.2.0.

В раннем тесте дополнительная песочница мешала запуску Electron. Текущая версия использует PF и запускает подписанный Claude.app без дополнительных параметров сети.

## Kill switch для Claude Desktop в Debian VM

Подготовлена отдельная VM `tunnelguard-desktop` в `.build/desktop-lima` с официальным Claude Desktop 6.28899.6 для Linux ARM64. Гость закрыт `nftables` по умолчанию. На холодном старте Lima проверяет частный SSH-порт и переходит на `vsock`. Перед запуском Claude все интерфейсы гостя, кроме loopback, выключаются. Обратный SSH-проброс ведёт к проверяемому прокси V2Pro на Mac. Запуск и подключение к окну описаны в [README.md](README.md).

Проверены окно и Chromium-рендерер с seccomp, HTTPS от гостя, блокировка прямых IPv4/IPv6, DNS и UDP, симуляция потери и восстановления маршрута и остановка прокси. `SIGKILL` тестового прокси разорвал действующий гостевой CONNECT, прямой TCP остался заблокирован. Повторный запуск с VNC и завершение через `Ctrl+C` прошли дважды. Проверки проводились с временным профилем или без входа в учётную запись. Хостовый V2Pro оставался подключённым.

## Следующий практический шаг

Нативный Claude работает с отдельной группой PF и своим обычным профилем. Фильтр закрывает соединения на других интерфейсах, а также IPv6. Проверка продолжительного восстановления после переподключения V2Pro и трафика системных служб вынесена в отдельные испытания.

1. Держать V2Pro включённым, поскольку через него идёт текущий трафик пользователя. Проверять отказ и восстановление соединений симуляцией внутри запускатора. Проверка реального обрыва и захват на физическом интерфейсе отложены.
2. Проверить обычную интерактивную сессию Claude Code на явно выбранном полнотуннельном профиле. Фоновые сессии Claude Code могут стартовать через отдельный процесс и требуют отдельной проверки.
3. Проверить вход и обычную работу в гостевом Claude Desktop на согласованной учётной записи и доверенном IP выхода. Нативная macOS-сборка остаётся вне гостевой защиты. Альтернативы описаны в [ARCHITECTURE.md](ARCHITECTURE.md).

## Команды

```sh
sh Packaging/macOS/build-app.sh
python3 -B Scripts/tunnelguard-desktop.py --prepare
python3 -B Tests/check_free_launcher.py
python3 Scripts/tunnelguard-run.py --check-v2pro
sh Packaging/macOS/build-lab.sh
python3 Tests/check_profile.py "$(swift build --show-bin-path)/tunnelguard-check-profile"
xcode-select -p
security find-identity -v -p codesigning | awk '/valid identities found/ {print $1}'
```

В ограниченном окружении Codex сборка прошла с кешем модулей в `/tmp` и флагами `--disable-sandbox --manifest-cache none` у SwiftPM. Во внешнем терминале сначала использовать обычный `swift build`.

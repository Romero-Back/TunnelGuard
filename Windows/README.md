# TunnelGuard Windows x64 Preview

Это экспериментальная сборка для Windows 11 x64. Она проверяет маршрут и выходной IPv4 до запуска выбранного `Claude.exe`. Штатная фильтрация WFP блокирует прямые соединения этого файла. Во время сеанса разрешается только TCP к локальному прокси, который привязывает сетевые сокеты к выбранному VPN-интерфейсу.

## Первый тест

1. Распакуй ZIP целиком, открой `TunnelGuard.exe` и подтверди запрос Windows UAC.
2. Закрой Claude. Укажи локальный `Claude.exe`. Прямой запуск официального MSIX и работа Cowork со своим сервисом пока не подтверждены.
3. Включи полнотуннельный VPN. В TunnelGuard нажми «Найти маршрут» и сверь полученный индекс с VPN-адаптером. Список интерфейсов можно посмотреть командой `Get-NetIPInterface -AddressFamily IPv4` в PowerShell.
4. Введи заведомо известный публичный IPv4 выхода выбранного VPN. Сначала нажми «Проверить сеть». После успешной проверки выбери «Проверить и запустить». При ошибке приложение оставит блокировку и не откроет Claude.
5. TunnelGuard передаёт Claude отдельный каталог профиля для теста. Если Claude покажет рабочий профиль, закрой окно и останови проверку. На этом этапе реальный Claude и VPN пользователя не тестировались.

Кнопка «Остановить» закрывает разрешение прокси. После закрытия TunnelGuard постоянные правила остаются. Чтобы вернуть доступ обычному приложению, открой TunnelGuard и выбери «Снять блокировку…». Чтобы сменить защищаемый файл после переустановки Claude, сначала закрой Claude, сними старое правило и настрой новый путь.

## Границы

WFP в этой сборке идентифицирует выбранный исполняемый файл по его системному пути. Службы, другие исполняемые файлы, новые пути после обновления, Cowork, сетевые запросы от системных служб и отдельно скачанные копии находятся вне этой границы. Прямой запуск через меню Windows возможен, сетевые соединения выбранного файла блокируются правилом. VPN должен предоставлять IPv4-маршрут на выбранном интерфейсе. Упаковка портативная, автоматического обновления Windows пока нет.

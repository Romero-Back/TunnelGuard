# Модель безопасности

В текущей сборке песочница применяется до запуска команды. Она разрешает её сокетам исходящий TCP на выделенный loopback-порт прокси. Прямой TCP на другой порт, UDP и известные системные пути DNS запрещены. Прокси принимает `CONNECT` к публичным адресам на порт 443.

## Условия разрешения запроса

1. Из конфигурации известен публичный VPN IP соответствующего семейства.
2. Cloudflare и ipify сообщают одинаковый разрешённый IP, а их HTTPS-сокеты привязаны к тому же туннелю. Для этих проверок передаются стандартные запросы к сервисам. Сервисы видят IP выхода. До успешной проверки прокси удерживает DNS-имя приложения локально.
3. Системный маршрут назначения указывает на текущий V2Pro. Сокет привязывается к найденному интерфейсу до `connect()`. Ошибка маршрута, привязки или проверки закрывает соединение. Успешное наблюдение действует 15 секунд для конкретного интерфейса и семейства, затем для активного трафика требуется новое подтверждение.

Аварийное завершение прокси закрывает его сокеты. Уже запущенный дочерний процесс остаётся в песочнице. Режим диагностики доступен без ожидаемого IP и принимает только `example.com`.

## Границы проверки

- Тесты покрывают собственные сетевые сокеты команд и обычных потомков. Уже запущенные процессы, внешние приложения и отдельно запущенные фоновые службы не контролируются.
- Привязка действует до интерфейса V2Pro. Способ, которым сам V2Pro обрабатывает пакет после приёма, задаёт VPN-клиент. Совпадение контрольных IP не доказывает одинаковый маршрут всех доменов при split tunneling. Для такого режима защита не заявляется.
- Оснований заявлять отсутствие утечек при реальном отключении VPN пока нет. Требуется захват на физических и виртуальных интерфейсах на изолированном стенде.
- Claude Desktop, удалённые агенты, фоновые сессии Claude Code и его отдельные механизмы песочницы требуют самостоятельной проверки. Статус диагностики не обозначает активную системную защиту.

## Режим Claude Desktop в VM

Ядро гостевого Linux запрещает IPv4 и IPv6 через `nftables`, независимо от процесса Electron. Частное DHCP и ответы на проверку SSH разрешены только для загрузки Lima. Перед запуском Claude все гостевые интерфейсы, кроме loopback, отключаются. Внешний HTTPS возможен через обратный SSH-проброс к прокси на Mac после проверки V2Pro. Прямой DNS, UDP и QUIC из гостя запрещены. При закрытии прокси в госте нет альтернативного интернет-маршрута.

Администратор гостя считается доверенным. Claude работает без `sudo`. Общих каталогов Mac и передачи SSH-агента в гостя нет. Доступ к VNC идёт через loopback на обеих сторонах и использует случайный пароль на время сессии. Нативный Claude Desktop на Mac и его уже запущенные процессы находятся вне этой VM.

## Нативный Claude Desktop

Приложение запускается со своим обычным UID и выделенным GID `tunnelguard_claude`. PF разрешает этому GID IPv4 TCP и UDP на интерфейсе V2Pro и блокирует те же протоколы на остальных интерфейсах, а также IPv6. Разрешающие правила не создают состояние, которое могло бы пережить изменение маршрута. Перед запуском Claude и перед переключением в его окно TunnelGuard проверяет разрешённый публичный IPv4 в двух источниках. Из выделенного GID он проверяет отказ на прямом локальном TCP-порту и успешное TCP-соединение через тот же интерфейс V2Pro. Ошибка любой из проверок отменяет открытие Claude.

Защита относится к сокетам выделенной группы. Системный DNS и другие службы macOS, которые могут обращаться в сеть от своего имени, не попадают под правила группы. Публичный IPv4 подтверждается на момент проверки. Если V2Pro применяет раздельную маршрутизацию внутри своего интерфейса, PF проверяет только попадание пакета на интерфейс V2Pro.

## Панель, аварийная пауза и наблюдение

- Маршруты опрашиваются для фиксированных контрольных адресов. Статус службы основан на последнем результате и счётчике её выполнений в launchd. Это не счётчик соединений и не чтение всех правил PF. При потере контрольного маршрута или здоровья помощника открытая панель пытается завершить управляемый Desktop. Частота опроса около четырёх секунд. Отдельный постоянный watchdog вне процесса TunnelGuard не устанавливается.
- Panic сначала записывает пользовательскую аварийную блокировку, затем запрашивает остановку задачи Desktop. Управляемый прокси Code отвергает новое подключение и прекращает пересылку при следующей проверке. Возобновление выдаёт новый идентификатор допуска. Предыдущий процесс Code остаётся в старом сеансе Terminal без доступа. Сочетание ⌥⇧⌘P работает, пока запущен TunnelGuard и macOS зарегистрировала сочетание.
- Leak Test проверяет прямой TCP к двум прослушиваемым локальным портам IPv4/IPv6 из группы Desktop, затем подтверждает TCP через V2Pro. Результат не покрывает системный DNS, UDP, трафик делегированных служб или реальный обрыв VPN. Отпечаток содержит наблюдаемый клиент, интерфейс и подтверждённый IPv4. Название профиля, протокол, регион и данные из VPN-конфига недоступны через используемые проверки.
- Журнал записывает категории событий и время в локальные настройки. В журнал не поступают адреса назначения, содержимое запросов и вывод Claude.

## Подпись обновлений

Sparkle проверяет подпись ленты и Ed25519-подпись DMG до распаковки. В приложении находится публичный ключ. Закрытый ключ передаётся инструменту подписи из секрета GitHub Actions через stdin. Резервная копия ключа хранится в связке ключей сборочного Mac под учётной записью Sparkle `tunnelguard-release`.

## Ограничение запуска Claude Desktop

Этот режим добавляет файловое ограничение для управляемой копии Claude. Включение и откат требуют администратора. Помощник и защищённая копия находятся в каталоге под управлением root. У пользователя сохраняется обычный UID. Закрытая группа файловой системы доступна процессу после входа через помощник, а прежняя эффективная группа остаётся под правилами PF.

Правило sudoers разрешает конкретному пользователю запустить только фиксированный помощник без аргументов командной строки. Помощник сбрасывает root-права и переменные окружения перед запуском доверенной копии проверяющего кода. Только после сверки публичного IPv4 двумя источниками, подтверждения текущего V2Pro и проверки PF выполняется фиксированный бинарник Claude. При ошибке обычный запускатор не используется как запасной вариант.

Режим защищает от случайного прямого запуска этой копии. Администратор или отдельная устанавливаемая копия находятся вне этой границы. Уже запущенный Claude может получить фокус из Dock. Оригинал сохраняется для отката. Перед обновлением Claude необходимо восстановить обычный запуск, обновить Claude и повторно включить режим.
